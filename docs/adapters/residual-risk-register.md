# Adapter Residual-Risk Register (credential-gated providers)

> Closes LAY-3582 / T8. Consolidates the residual-risk notes that the
> credential-gated adapters document inline in their test modules.

Five adapters wrap services we have no credentials for in base CI
(`azure_openai`, `bedrock`, `google_vertex`, `bedrock_agents`, `agentforce`).
For these, the `doubles` tier in [`tests/adapter_manifest.toml`](../../tests/adapter_manifest.toml)
runs **deterministic doubles** — hand-built or seeded response objects driven
through the *real* SDK seams (real client objects, real serialization/parsing,
no network). They run in base CI, **not** the live matrix. The doubles prove the
parse/emit path against a realistic shape, but they cannot exercise the real
credential flow, transport, or service-side behaviour. The **residual** column
below is exactly what only a real credentialed call could catch — the surface
that stays unverified until a live-smoke session runs against actual creds.

Where a `recorded` tier exists, the fixture's provenance matters: `bedrock` and
`bedrock_agents` replay a **live-captured** response (Amazon Nova), so their
residual is narrowed to shapes the capture didn't include. `azure_openai` and
`google_vertex` have **no creds on any machine**, so their `recorded` fixtures
are *seeded* and flagged `captured_at: pending-creds` — to be replaced with a
live capture when creds exist. `agentforce` replays a real captured Salesforce
session.

| Adapter | What the double covers | Residual (untestable without live creds) | Mitigation / notes |
|---|---|---|---|
| `azure_openai` | A real `openai.AzureOpenAI` client built against a fake endpoint with an `httpx.MockTransport` injected through the `http_client=` seam: deployment URL routing, the `api-version` query param, the `api-key` header, and response parsing all run through the real SDK with no network. Response JSON mirrors a real Azure `chat.completions` payload incl. `prompt_filter_results` / `content_filter_results`. | The actual Azure subscription, credential exchange, and live transport are never exercised. The `recorded` fixture is *seeded* (no Azure creds on any machine), flagged `captured_at: pending-creds` — only a live capture confirms the real wire shape and any Azure-specific deviations. | Seeded recorded fixture deserializes through the real `AzureOpenAI` client over `MockTransport`; replace with a live capture when creds exist (the freshness check is the future live-smoke session). |
| `bedrock` | A real `bedrock-runtime` boto3 client (region `us-east-1`, static fake creds) driven through `botocore.stub.Stubber`, so requests pass real botocore parameter validation and serialization with no network. `invoke_model` body is an Anthropic Messages response built from real `anthropic` SDK types (`Message`/`TextBlock`/`Usage`) in a `StreamingBody`; `converse` response carries `output.message`, `usage` (inputTokens/outputTokens/totalTokens), `stopReason`, and `metrics`. | A real AWS account / model access, IAM credential flow, and live transport are not exercised. The hand-built doubles fabricate token counts and synthesize the body, so members only present on real responses (e.g. the `cacheReadInputTokenCount` / `cacheWriteInputTokenCount` usage members) are not covered by the doubles. | A `recorded` tier replays a **real captured Amazon Nova response** (both Converse and Converse-shaped `invoke_model`) and includes the cache token members the fabricated doubles never carried. |
| `google_vertex` | The adapter is duck-typed (wraps any object exposing `generate_content` / `generate_content_async`), so the doubles are plain classes mirroring the real `vertexai.generative_models.GenerationResponse` shape: `candidates[].content.parts[].text`, enum-like `finish_reason` (`.name`/`.value`), and `usage_metadata` with `prompt_token_count`/`candidates_token_count`/`total_token_count` (+ `thoughts_token_count` on newer SDKs). The extractors are also run against a **real** proto-backed `GenerationResponse` built via `from_dict` (no creds needed). | The real `vertexai.GenerativeModel` object, its credential flow, and the gRPC/REST transport remain unexercised (require GCP creds). Specifically: `vertexai`'s `GenerativeModel` stores a fully-qualified resource name (`publishers/google/models/<id>` or `projects/.../models/<id>`) in `_model_name`, which the adapter's `_strip_models_prefix` does not strip — whether **pricing lookups resolve** for real `vertexai` (vs. the `google-generativeai`-style `models/<id>` names that are covered) is unverifiable without live access. | Extractors validated against a real proto-backed `GenerationResponse` via `from_dict`. The `recorded` fixture is *seeded*, flagged `captured_at: pending-creds`; needs a live capture to confirm the real-`vertexai` pricing-resolution path. |
| `bedrock_agents` | A real `bedrock-agent-runtime` client driven via a `Stubber`, with a fake single-read `completion` EventStream (`_FakeEventStream`) injected into `parsed` through an `after-call` hook registered *before* the adapter's. Asserts both **transparency** (the customer's `for event in response['completion']` sees every original event in order, unmodified, exactly once — the adapter must not consume the single-use stream) and **emission** (`agent.input` + `environment.config` at call time, then per-trace `model.invoke` (+ priced `cost.record`), `tool.call` (action group), knowledge_base, collaborator `agent.handoff`, `agent.error` (failureTrace), and a final `agent.output`; the trace is flushed only after the stream is drained). Rebuilt 2026-06-17 from a live-captured `InvokeAgent` stream (agent `9WBVYFT6RB` on Nova, us-east-1). | botocore's `Stubber` cannot synthesise an event stream, so the stream is a fake injected stand-in. Live-validated paths are model-invocation, output (chunk), and proxy transparency only. The **action-group / knowledge-base / collaborator / failure** trace shapes follow the AWS Bedrock Agents `TracePart` API but the live test agent has no action groups or knowledge bases, so those shapes **must be re-confirmed against a richer live trace**. | A `recorded` tier replays the real captured completion stream (Nova, agent `9WBVYFT6RB`, "what is 2+2") through the EventStream-proxy seam — the regression class the original fictional schema (top-level `outputText`/`trace`) slipped past every non-live layer. |
| `agentforce` | Exercises the **real** `_SalesforceConnection` class (unlike `test_agentforce.py`, which mocks it): OAuth client-credentials token exchange, SOQL query URL construction, Bearer auth headers, and `nextRecordsUrl` pagination, over an `httpx.MockTransport`. Serves realistic Session Tracing Data Model payloads (`ssot__AiAgent*__dlm`) shaped exactly like the rows a live `describe` returned (UUID business ids in `ssot__Id__c`, the `NOT_SET` sentinel, **no token fields**). Injection seam: the module-level `httpx` name in `agentforce.py` is monkeypatched so `Client(**kwargs)` returns a real `httpx.Client` bound to the MockTransport (no src changes). | A real Salesforce org, the live OAuth grant, and the actual STDM query responses are not exercised against the platform. A future STDM **schema change** would not be caught by the doubles (the records are realistic but locally authored). The adapter once shipped on a *fictional* schema (made-up DMOs), rewritten to the real `ssot__` STDM in LAY-3599. | A `recorded` tier replays a **real captured Salesforce session** — the OAuth token exchange plus the seven STDM SOQL responses, captured live from the dev org and committed scrubbed — through the real `_SalesforceConnection` over `MockTransport`; a future STDM shape change would surface there. |
